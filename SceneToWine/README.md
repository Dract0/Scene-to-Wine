# Scene-Based Wine Recommender

A wine recommendation application that combines a vision model, sentence
embeddings, and a trained price-prediction model to recommend wines suited to
a user-uploaded scene image.

## System overview

The application is organized into three components:

**Component A — Trained price-prediction model.** A LightGBM regression
predicts wine price from the description text (TF-IDF unigrams and bigrams,
with reviewer price-vocabulary filtered out), variety, country, province,
rating, and wine age (extracted from the title). Evaluated on a held-out
test set and via 5-fold cross-validation.

**Component B — Semantic retrieval.** A vision model converts the scene
image to structured attributes (setting, mood, formality, time of day,
suggested wine traits). Each wine in the indexed corpus is paired with an
LLM-generated profile describing occasions, moods, food pairings, and
stylistic adjectives. Both sides are encoded with
`sentence-transformers/all-MiniLM-L6-v2` and matched by cosine KNN.

**Component C — Decision layer.** The top KNN candidates are re-ranked by a
weighted combination of scene similarity and the price model's
predicted-vs-actual value ratio. Results are returned with a value tag
(Excellent / Good / Fair / Premium) and an LLM-generated pairing rationale.

## Performance

### Price model (Component A)

Single-split test set (15% held out, 18,133 wines):

| Model | MAE (USD) | RMSE (USD) | R² (log) |
|---|---|---|---|
| Baseline (variety mean) | 15.78 | 30.14 | 0.200 |
| Ridge (TF-IDF + OHE + age) | 11.46 | 22.93 | 0.617 |
| **LightGBM (TF-IDF + OHE + age)** | **10.38** | **20.73** | **0.684** |

5-fold cross-validation:

| Model | Mean MAE (USD) | Std |
|---|---|---|
| Ridge | 11.49 | ±0.09 |
| LightGBM | 10.51 | ±0.09 |

### Retrieval quality (Component B)

Macro precision@5 across 12 hand-crafted scene→keyword test cases: **0.967**.
Twelve of twelve cases retrieved at least three relevant wines in the top
five. Mean of 4.33 distinct varieties per top-5 indicates the retrieval is
not collapsing to a single wine type.

## Local development

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...
streamlit run app.py
```

The application opens at `http://localhost:8501`. First load downloads the
sentence-transformer weights (~30s, cached afterwards).

## Deployment to Streamlit Community Cloud

1. Push this directory to a GitHub repository.

   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git remote add origin https://github.com/<owner>/<repo>.git
   git push -u origin main
   ```

2. Connect the repository at https://share.streamlit.io. Set the main file
   to `app.py` and Python version to 3.11.

3. Add the API key as a secret. In the application's Settings → Secrets:

   ```toml
   ANTHROPIC_API_KEY = "sk-ant-..."
   ```

The first deploy takes ~3 minutes for dependency installation. Subsequent
launches are near-instant.

## Configuration

Available controls in the sidebar:

- **Maximum price** — hard filter on the candidate pool
- **Wine type** — hard filter (red, white, rosé, sparkling)
- **Food pairing / mood preference** — soft inputs incorporated into the query embedding
- **Re-ranking weight** — slide between pure scene similarity (0.0) and pure
  predicted-value ranking (1.0); default 0.5
- **Number of recommendations** — 3 to 7

## Reproducing the artifacts

The artifacts in this repository are generated by
`wine_recommender_backend_v2.ipynb` (Colab notebook, not included in this
repo). The notebook trains the price model, generates wine vibe profiles via
the Claude API, builds the embedding index, and runs retrieval evaluation.

To rebuild from the source dataset
([Kaggle: Wine Reviews](https://www.kaggle.com/datasets/zynicide/wine-reviews)),
upload the CSV to the notebook and run all cells. The vibe-profile
generation step takes 10–15 minutes and costs approximately $2–3 in Haiku
API calls.

## Limitations

- **Indexed corpus is small.** Only 1,250 wines are indexed (out of ~130,000
  in the source dataset), bounded by API budget for vibe-profile generation.
  Recommendations are drawn from this subset, which over-represents
  highly-rated wines (≥87 points) and Pinot Noir, Chardonnay, and Cabernet
  Sauvignon.
- **Residual price-vocabulary leakage.** Our stopword scrub removed the most
  obvious price terms ("value", "bargain", "affordable"), but residual
  reviewer slang ("steal", "buck", "everyday") still appears in feature
  importance. A second-pass scrub would tighten the model further.
- **Retrieval evaluation uses self-derived ground truth.** The 12 test
  cases are matched against the same vibe-vocabulary used to build the
  index. Human-rated relevance judgments would be a stronger benchmark.
- **No user personalization.** The system has no memory of past
  recommendations or user preferences across sessions.
